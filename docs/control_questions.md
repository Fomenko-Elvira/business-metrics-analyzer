# Ответы на контрольные вопросы

## Практическое занятие № 1
### Настройка среды разработки и управление версиями

## 1. Чем отличается Git от GitHub?

Git — это распределённая система контроля версий, предназначенная для отслеживания изменений в проекте. С её помощью можно сохранять историю разработки, создавать отдельные ветки и объединять внесённые изменения.

GitHub — это облачная платформа для размещения Git-репозиториев и организации совместной работы. Она позволяет хранить проекты в удалённом репозитории, обмениваться изменениями и использовать Pull Request для проверки и объединения результатов работы.

## 2. Для чего используется виртуальное окружение Python?

Виртуальное окружение Python необходимо для создания отдельной среды для конкретного проекта. Оно позволяет устанавливать нужные библиотеки и их версии независимо от других проектов, находящихся на компьютере.

В данной практической работе используется виртуальное окружение `.venv`, в котором устанавливаются необходимые зависимости проекта, в том числе библиотеки `pandas` и `matplotlib`.

## 3. Что такое commit, branch, remote, pull request?

**Commit** — это сохранённая фиксация изменений, которая записывается в историю Git-репозитория.

**Branch** — отдельная ветка разработки, в которой можно работать над определённой задачей, не изменяя сразу основную версию проекта.

**Remote** — удалённый репозиторий, связанный с локальным проектом. Например, репозиторий, размещённый на GitHub.

**Pull Request** — запрос на объединение изменений из одной ветки в другую. Перед слиянием другие участники могут просмотреть внесённые изменения и проверить их.

## 4. Зачем нужен файл `.gitignore`?

Файл `.gitignore` используется для указания файлов и папок, которые не должны добавляться в Git-репозиторий.

В него можно включить виртуальное окружение `.venv`, временные файлы, служебные файлы среды разработки и другие локальные данные, которые не нужны в удалённом репозитории.

Использование `.gitignore` позволяет поддерживать репозиторий в чистом состоянии и не загружать на GitHub лишние файлы.

## 5. Как организовать командную работу над бизнес-приложением с помощью Git?

Для командной разработки участники могут использовать общий удалённый репозиторий и создавать отдельные ветки для выполнения своих задач.

Разработчик сначала получает актуальную версию основной ветки `main`, после чего создаёт собственную ветку и вносит необходимые изменения. Затем изменения фиксируются с помощью commit и отправляются в удалённый репозиторий командой `push`.

После этого создаётся Pull Request. Другой участник команды может проверить внесённые изменения, оставить комментарий или одобрить их. После проверки ветка объединяется с `main`.

После слияния участникам необходимо обновить локальную версию основной ветки командой `git pull origin main`.

## 6. Какие файлы обязательно должны быть в репозитории учебного проекта?

В репозитории учебного проекта должны находиться основные файлы, необходимые для его запуска и описания:

- `.gitignore` — определяет файлы и папки, которые Git не должен отслеживать;
- `README.md` — содержит описание проекта, его назначение и инструкцию по запуску;
- `requirements.txt` — содержит список зависимостей Python;
- `main.py` — основной файл программы.

После выполнения домашнего задания в проект также добавляется:

- `docs/business_requirements.md` — документ с описанием бизнес-требований к учебному приложению.

## 7. Что произойдёт, если два разработчика изменят один и тот же файл в разных ветках?

Пока разработчики работают в разных ветках, изменения сохраняются независимо друг от друга.

При последующем объединении веток Git сравнивает изменённые версии файла. Если изменения были сделаны в разных его частях, они обычно объединяются автоматически.

Если оба разработчика изменили одинаковые или пересекающиеся строки, может возникнуть конфликт слияния — `merge conflict`. В таком случае необходимо вручную определить, какой вариант изменений должен остаться, сохранить исправленный файл и после этого завершить слияние веток.
